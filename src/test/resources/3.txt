1.2 POPIS PROCESOV
PROCES Zadanie (vypracovaný študentom, nie je zakreslený v diagrame)
Spúšťanie
zadanie <číslo portu 1> <číslo portu 2>
Funkcia
Parametre hlavného programu sú čísla portov pre servery Serv1 (TCP) a Serv2 (UDP). Tieto čísla je potrebné týmto procesom odovzdať. Program Zadanie nech vyhradí všetky zdroje (pre medziprocesovú komunikáciu) a nech spustí všetky procesy. Všetky procesy nech sú realizované ako samostatné programy.

PROCES Pr
Spúšťanie
proc_pr <pid procesu P1> <pid procesu P2>
<id čítaciaho konca rúry R1> <id zapisovacieho konca rúry R2>
Funkcia
Proces Pr pošle signál SIGUSR1 svojmu hlavnému procesu (Zadanie) na signalizáciu, že je pripravený. Proces Pr si údaje bude žiadať: 
    • Ak pošle signál (SIGUSR1) procesu P1, nech tento proces (P1) zapíše slovo prečítané zo súboru p1.txt.
    • To isté platí aj pre proces P2 a p2.txt. Teda, ak proces Pr pošle signál (SIGUSR1) procesu P2 nech do rúry R1 zapíše slovo proces P2 zo súboru p2.txt.
Proces Pr k slovu prijatému z rúry R1 pridá svoju značku a zapíše nové slovo do rúry R2. 

PROCES S
Spúšťanie
proc_s <id zdieľanej pamäte SM1> <id semaforu S1> <id zdieľanej pamäte SM2> <id semaforu S2>
Funkcia
Proces S pošle signál SIGUSR1 svojmu hlavnému procesu (Zadanie) na signalizáciu, že je (proces S) pripravený. Proces S príjme slovo zo zdieľanej pamäte SM1 so synchronizáciou semaforom S1 (pozri časť o semaforoch v časti „Popis komunikácie“), pripíše k nemu svoju značku a zapíše ho do zdieľanej pamäte SM2 so synchronizáciou semaforom S2. 

PROCES Serv1
Spúšťanie
proc_serv1 <číslo portu 1> <číslo portu 2>
Funkcia
Proces Serv1 vytvorí TCP server (na porte <číslo portu 1>), ktorý bude prijímať TCP pakety. Server prijaté slová označí svojou značkou a pošle ich ďalej na UDP server (port <číslo portu 2>). Čísla portov 1 a 2 sú argumenty hlavného procesu (pozri kapitolu „PROCES Zadanie“). Proces Serv1 pošle signál SIGUSR1 svojmu hlavnému procesu (Zadanie) na signalizáciu, že je (proces Serv1) pripravený. TCP aj UDP server nech vytvorený na lokálnom počítači, teda na počítači „127.0.0.1“ (pozor, nie „localhost“!).

1.3 POPIS KOMUNIKÁCIE 
Semafor S1
Pre semafor S1 je potrebné vytvoriť dvojicu semaforov. Proces T nech sa riadi podľa semaforu S1[0] a proces S sa bude riadiť podľa semaforu S1[1], pričom nastavený semafor S1[0] (rozumej nastavený na hodnotu 1) nech znamená, že proces T môže zapisovať do zdieľanej pamäte (SM1). Nastavený semafor S1[1] nech znamená, že proces S môže zo zdieľanej pamäte (SM1) údaje čítať.

Semafor S2
Pre semafor S2 je potrebné vytvoriť dvojicu semaforov. Proces S nech sa riadi podľa semaforu S2[0] a proces D sa bude riadiť podľa semaforu S2[1]. Pričom nastavený semafor S2[0] (rozumej nastavený na hodnotu 1) nech znamená, že proces S môže zapisovať do zdieľanej pamäte (SM2). Nastavený semafor S2[1] nech znamená, že proces D môže zo zdieľanej pamäte (SM2) údaje čítať.
Príklad komunikácie medzi procesom T a procesom S – semafor S1
Pozn.: Pre semafor S2 je to analogické.
Hodnota semaforu	Význam
0	červená
1	zelená
Proces T sa riadi semaforom S1[0] a proces S sa riadi semaforom S1[1]. To znamená, že kým ma proces T na svojom semafore (S1[0]) hodnotu 0 (t.j. červená) – tak stále čaká. To isté platí pre proces S. To znamená, že kým proces S má na svojom semafore (S1[1]) hodnotu 0 (červená) – to znamená, že musí čakať.
Semafor treba inicializovať do nasledovného stavu:
S1[0] = 1 (zelená/môžeš)	S1[1] = 0 (červená/stoj)
- tento stav znamená, že proces T môže do zdieľanej pamäte zapisovať. Proces S čaká, má červenú, nemôže čítať.
Proces T má zelenú (teda môže zapisovať), lebo má svoj semafor (S1[0]) nastavený na hodnotu 1 (zelená). Teda do zdieľanej pamäte zapíše svoje údaje. Teraz je potrebné, aby proces T umožnil procesu S údaje čítať. Preto zmení semafory na nasledovný stav:
[Najprv zmení svoj semafor (semafor S1[0]) z hodnoty 1 na hodnotu 0 (teda zo zelenej na červenú) a semafor procesu S (teda S1[1]) zmení z hodnoty 0 na hodnotu 1 (z červenej na zelenú, aby mu naznačil, že údaje sú zapísané a môže ich teda čítať.)]
S1[0] = 0 (červená/stoj)	S1[1] = 1 (zelená/môžeš)
- tento stav znamená, že proces T nemôže do zdieľanej pamäte zapisovať, má čakať. Proces S má zelenú, má v zdieľanej pamäti pripravené údaje a môže údaje z pamäte prečítať.
Teraz už môže semafor S zo zdieľanej pamäte údaje prečítať, lebo jeho semafor (S1[1]) sa zmenil z hodnoty 0 (červená) na hodnotu 1 (zelená). Prečíta teda údaje zo zdieľanej pamäte a vymení farby semaforov (t.j. zmení sebe zo zelenej na červenú – z 1 na 0 – a procesu T zmení z červenej na zelenú – z 0 na 1 – aby mohol do pamäte zapisovať).

Súbory p1.txt, p2.txt a serv2.txt
Súbory p1.txt a p2.txt budú obsahovať slová (rozumej reťazce znakov každé v novom riadku), pričom veľkosť slova počas putovania medzi procesmi nepresiahne dĺžku 150 znakov. Súbor serv2.txt nech obsahuje výsledné slová zapísané každé v samostatnom riadku.
Poznámka: Pre účely vývoja programov a testovania je možné programy Pr, S a Serv1 stiahnuť zo stránok systému na odovzdávanie zadaní.
Upozornenie:
Pozor, nachádzate sa v paralelnom prostredí! To znamená, že poradie vykonávania procesov nemusí byť rovnaké na rôznych systémoch. Preto dbajte na synchronizáciu a vyhnete sa problémom „predbiehania“ procesov!
2 Dodefinovanie zadania
Naša implementácia, hoci funkčná, vykazuje obmedzenia, najmä pokiaľ ide o správne poradie spúšťania jednotlivých procesov. Ak sa nezachová stanovené poradie, program neskončí správne a niektoré procesy zostanú visieť. Toto obmedzenie vyžaduje dodatočné opatrenia pri správe a ladení v rámci programu.

3.2.2 Algoritmus procesu P2

proc_p2 <id pipe1 (write)>
    • Funkcia
        ◦ V prípade, že proces P2 zaregistruje signál z procesu PR, tak proces P2 otvorí súbor p2.txt a načíta z neho slovo do rúry P1. 
3.2.3 Algoritmus procesu D
    • Spúšťanie
proc_d <id shm2> <id S2> <port tcp>
    • Funkcia
        ◦ Proces D odosiela signál hlavnému procesu pomocou služby kill, ktorý informuje hlavný proces o spustení podprocesu D. Následne, proces D pomocou semafora S2, ktorého identifikačné číslo sme získali zo vstupu, zablokuje zapisovanie do zdieľanej pamäte shm2, načíta zo spomenutej zdieľanej pamäte jedno slovo a skrz tcp port budú následné dáta poslané na server.
3.2.4 Algoritmus procesu T
    • Spúšťanie
proc_t <id shm1> <id S1> <id P2 (read)>
    • Funkcia
        ◦ Proces T odosiela signál hlavnému procesu pomocou služby kill, ktorý informuje hlavný proces o spustení podprocesu T. Následne, proces T načíta slovo z rúry P2 a potom pomocou semafora S1, ktorého identifikačné číslo sme získali zo vstupu, povolí zapisovanie do zdieľanej pamäte shm1, načíta z rúry P2 jedno slovo a zapíše ho do zdieľanej pamäte shm1, po zapísaní sa zápis zablokuje prostredníctvom spomenutého semaforu S1.

4 Analýza problematiky
4.1 Vyhradenie zdrojov:
    • Problematika tohto zadania spočíva v zabezpečení prenosu informácií medzi jednotlivými procesmi. Tento prenos informácií praktizujeme pomocou rúr, semaforov a zdieľanej pamäte.
    • Proces Zadanie vyhradí rúry, semafory a zdieľanú pamäť pre medziprocesovú komunikáciu. Týmto zabezpečí synchronizáciu a komunikáciu medzi jednotlivými procesmi.


4.2 Spustenie procesov:
    • Proces Zadanie spustí nasledujúce procesy v tomto poradí (na poradí záleží):
        1. Serv1 (TCP server)
        2. Serv2 (UDP server)
        3. D (proces D)
        4. P1 (proces P1)
        5. P2 (proces P2)
        6. Pr (proces Pr)
        7. T (proces T)
        8. S (proces S)
4.3 Medziprocesová komunikácia:
    • Rúry, semafory a zdieľaná pamäť slúžia na komunikáciu medzi procesmi a zabezpečujú synchronizáciu ich činnosti.
    • Signály (SIGUSR1, SIGUSR2) sa používajú na signalizáciu medzi hlavným procesom (Zadanie) a potomkami.
4.4 Práca s sieťou:
    • Proces Serv1 vytvára TCP server na danom porte a prijíma TCP pakety.
    • Proces Serv2 vytvára UDP server na danom porte a prijíma UDP pakety.
4.5 Spolupráca procesov:
    • Procesy P1 a P2 spolupracujú s procesom Pr na prenose slov cez rúry R1 a R2.
    • Procesy T a S spolupracujú na zdieľanej pamäti shm1 a semaforoch S1.
    • Procesy S a D spolupracujú na zdieľanej pamäti shm2 a semaforoch S2.
4.6 Klady a zápory
    • Medzi klady patrí ľahká spustiteľnosť prostredníctvom procesu Zadanie, ktoré koordinuje chod všetkých procesov a ich potomkov. Zároveň problematiku komunikácie medzi hlavným procesom a jeho potomkami uľahčuje využívanie signálov (SIGUSR1, SIGUSR2).
    • Ohľadom záporov, nevýhodou centralizácie riadenia všetkých procesov iba skrz proces zadanie je situácia predstavujúca zlyhanie hlavného procesu, ktorej by predchádzalo zrútenie celého systému. Ďalšou nevýhodou je nedostatočná flexibilita systému, keďže hlavný proces môže byť náchylný na rôzne problémy (preplnenie rúr, vyčerpanie zdrojov). A keďže je dôležité, aby jednotlivé procesy boli oddelené časovými intervalmi, v prípade nedodržania týchto časových výluk by mohlo dôjsť k nesprávnej komunikácii medzi procesmi.
5 Popis navrhovaného riešenia:
5.1 Návrh riešenia
Vzhľadom na to, že sme neuviedli viac variant možných riešení daného problému, zameriame sa práve na riešenie so zameraním na využitie rúr na medziprocesovú komunikáciu, a potom procesy, semafory a zdieľanú pamäť na koordináciu a synchronizáciu. Riešenie taktiež využíva signály na signalizáciu medzi procesmi, pričom použitie rúr pre komunikáciu medzi P1, P2 a Pr umožňuje prenášanie informácií medzi procesmi. Je nutné podotknúť, že pre správne vykonanie jednotlivých procesov a postprocesov je nutné dodržať presné spúšťanie jednotlivých procesov, ktoré zahŕňa aj prvotné inicializovanie serverov serv1 a serv2.
5.2 Dátové štruktúry
    1. Rúry (P1 a P2):
    • Použité na komunikáciu medzi procesmi P1, P2 a Pr.
        ◦ P1(pipe): Rúra medzi P1 a Pr.
        ◦ P2(pipe): Rúra medzi P2 a Pr.
    2. Semaforové Sady (S1 a S2):
    • Dve semaforové sady pre synchronizáciu medzi procesmi T a S a procesmi D a S.
        ◦ S1: Sada semaforov pre T a S.
        ◦ S2: Sada semaforov pre D a S.
    3. Zdieľaná Pamäť (shm1 a shm2):
    • Dve oblasti zdieľanej pamäte pre komunikáciu medzi procesmi T a S a procesmi D a S.
        ◦  shm1: Zdieľaná pamäť pre T a S.
        ◦  shm2: Zdieľaná pamäť pre D a S.
    4. Serverová komunikácia (Serv1 a Serv2):
    • Procesy Serv1 a Serv2 využívajú komunikačné servery pre prijímanie a odosielanie dát.
    • Serverová komunikácia zabezpečuje koordinovaný prenos informácií medzi procesmi.
        ◦ Serv1:
            ▪ TCP server na porte zadanom v argumentoch, slúžiaci na prijímanie TCP paketov.
        ◦ Serv2:
            ▪ UDP server na porte zadanom v argumentoch, slúžiaci na prijímanie UDP paketov.
5.3 Spôsob synchronizácie
    • Semafor S1:
        ◦ Semaforová sada S1 zahrňuje dva semafory.
            ▪ S1[0] - používa sa pre synchronizáciu medzi procesmi T a S. Nastavený na hodnotu 1 umožňuje procesu T zapisovať do zdieľanej pamäte (shm1).
            ▪ S1[1] - používa sa pre synchronizáciu medzi procesmi S a T. Nastavený na hodnotu 1 umožňuje procesu S čítať údaje zo zdieľanej pamäte (shm1).
    • Semafor S2:
        ◦ Semaforová sada S2 zahrňuje dva semafory.
            ▪ S2[0] - používa sa pre synchronizáciu medzi procesmi S a D. Nastavený na hodnotu 1 umožňuje procesu S zapisovať do zdieľanej pamäte (shm2).
            ▪ S2[1] - Používa sa pre synchronizáciu medzi procesmi D a S. Nastavený na hodnotu 1 umožňuje procesu D čítať údaje zo zdieľanej pamäte (shm2).
5.4 Algoritmy
5.4.1 Algoritmus procesu P1
Algoritmus procesu P1 inicializujeme nastavením signal handlera (handler) pre spracovanie signálu SIGUSR1. Následne overíme, či proces P1 dostal správny počet argumentov (je iba jeden - identifikátor pipe). Pokračujeme otvorením súboru "p1.txt" na čítanie (O_RDONLY). Proces P1 po otvorení súboru pošle signál SIGUSR1 hlavnému procesu (Zadanie), aby signalizoval, že je pripravený na prácu.
Čítanie a odosielanie riadkov:
    • V nekonečnom cykle prebieha načítavanie jedného znaku zo súboru "p1.txt" do buffera.
    • Ak je znak koniec riadku ('\n'), zároveň je načítaný do buffera, a celý riadok sa pošle cez pipe procesu Pr.
    • Proces čaká na ďalší signál SIGUSR1, aby pokračoval v načítavaní a odosielaní ďalších riadkov.
Handler (funkcia):
    • Spracováva príjem signálu SIGUSR1.
    • Postupne načíta znaky zo súboru "p1.txt" do buffera, a keď nájde koniec riadku, pošle tento riadok cez pipe procesu Pr.
5.4.2 Algoritmus procesu P2
Algoritmus procesu P2 inicializujeme nastavením signal handlera (handler) pre spracovanie signálu SIGUSR1. Následne overíme, či proces P2 dostal správny počet argumentov (iba jeden - identifikátor pipe). Pokračujeme otvorením súboru "p2.txt" na čítanie (O_RDONLY). Proces P2 po otvorení súboru pošle signál SIGUSR1 hlavnému procesu (Zadanie), aby signalizoval, že je pripravený na prácu.
Čítanie a odosielanie riadkov:
    • V nekonečnom cykle prebieha načítavanie jedného znaku zo súboru "p2.txt" do buffera.
    • Ak je znak koniec riadku ('\n'), zároveň je načítaný do buffera, a celý riadok sa pošle cez pipe procesu Pr.
    • Proces čaká na ďalší signál SIGUSR1, aby pokračoval v načítavaní a odosielaní ďalších riadkov.
Handler (funkcia):
    • Spracováva príjem signálu SIGUSR1.
    • Postupne načíta znaky zo súboru "p2.txt" do buffera, a keď nájde koniec riadku, pošle tento riadok cez pipe procesu Pr.
5.4.3 Algoritmus procesu D
Algoritmus procesu D inicializujeme odoslaním signálu SIGUSR1 hlavnému procesu (Zadanie) na signalizáciu, že je pripravený na prácu. Následne prebieha inicializácia socketu pre komunikáciu s serverom, vytvorenie štruktúry pre serverovú adresu, a pripojenie sa na zdieľanú pamäť. Proces D vytvára socket a konfiguruje serverovú adresu s lokálnou adresou "127.0.0.1" a zadaným portom. Potom sa pripája na server.
V nekonečnom cykle prebieha odosielanie dát na server. Prvým krokom je zvýšenie hodnoty semafora, aby proces S nemohol zapisovať do zdieľanej pamäte. Následne sa dáta zo zdieľanej pamäte kopírujú do buffera a odosielajú na server. Po odoslaní sa buffer vyčistí a hodnota semafora sa zníži, aby proces S mohol pokračovať v zapisovaní do zdieľanej pamäte. Pauza na 1 sekundu zabezpečuje cyklický charakter odosielania dát.
5.4.4 Algoritmus procesu T
Algoritmus procesu T inicializuje niektoré premenné, vrátane buffera (line), následne kontroluje počet argumentov. Ak je počet argumentov nedostatočný, vypíše chybové hlásenie a skončí s chybou. Ďalej konvertuje identifikačné čísla semaforu (S1), zdieľanej pamäte (shm1) a rúry (P2) z argumentov.
Následne sa pripojí na zdieľanú pamäť pomocou shmat a odosiela signál SIGUSR1 hlavnému procesu (Zadanie) signalizujúc, že je pripravený na prácu.
V nekonečnom cykle sa čaká na príchod dát z rúry (P2). Pri každom príchode znaku sa postupne ukladá do buffera (line), až kým nenájde koniec riadku '\n'. Po načítaní riadku sa povoli zapis semaforom (S1), zapisuje sa do zdieľanej pamäte shmnaddr a po zápise sa zablokuje ďalši zapis semaforom (S1).
5.4.5 Algoritmus procesu Serv2
Algoritmus procesu serv2 inicializuje niektoré premenné, vrátane bufferu (buf) a kontroluje počet argumentov. Ak je počet argumentov neplatný, program skončí s chybou. Následne konvertuje identifikačné číslo portu zo vstupných argumentov.
Vytvára socket na komunikáciu prostredníctvom UDP. Nastavuje serverovú adresu a skúša pripojiť sa k nej. Ak nastane chyba, vypíše chybové hlásenie.
Otvára súbor "serv2.txt" na zápis (alebo vytvára, ak neexistuje) a inicializuje premennú i na nulu. Odosielajú sa signály SIGUSR1 hlavnému procesu (Zadanie) na signalizáciu pripravenosti na prácu.
V nekonečnom cykle (alebo do odoslania 10 správ) čaká na príchod dát zo servera. Pri každom príchode dát sa tieto dáta zapisujú do súboru "serv2.txt". Po zapisovaní dát sa hodnota i zvýši o 1 (inkrementácia). Ak je i väčšie alebo rovné 10, cyklus sa ukončí.
Po ukončení cyklu sa odosiela signál SIGUSR2 hlavnému procesu na signalizáciu dokončenia práce.
5.4.6 Algoritmus procesu Zadanie
Hlavný proces – proces Zadanie inicializuje všetky potrebné premenné, rúry, semafory a zdieľanú pamäť. Vytvára potomkov podľa počtu jednotlivých procesov a spúšťa ich. Počas spúšťania potomkov čaká na prijatie signálu SIGUSR1 od každého z potomkov, čím sa signalizuje, že sú pripravení na prácu. Po úspešnom spustení všetkých potomkov čaká na prijatie signálu SIGUSR2, ktorým sa signalizuje ukončenie všetkých procesov.
Zároveň vytvára rúry, semafory a zdieľanú pamäť, inicializuje ich a vytvára potomkov. Každý potomok má priradenú svoju úlohu, ktorú vykonáva podľa zadania.
V prípade chyby pri vytváraní rúr, semaforov alebo zdieľanej pamäte vypíše chybové hlásenie a ukončí program. Po spustení každého potomka čaká na príjem signálu SIGUSR1, ktorým každý potomok signalizuje, že je pripravený na prácu.
Po úspešnom spustení všetkých potomkov čaká na príjem signálu SIGUSR2, ktorým hlavný proces signalizuje ukončenie všetkých potomkov.
Po ukončení všetkých potomkov sa hlavný proces stará o správne uzavretie a odstránenie rúr, semaforov a zdieľanej pamäte.

8.3 Dátové štruktúry
    1. struct sockaddr_in server_addr, client_addr:
Štruktúra sockaddr_in je využívaná v procesoch pracujúcich so sieťovým socketom. Obsahuje informácie o serverovej a klientovej adrese.
struct sockaddr_in {
    short            sin_family;   // typ adresy (napr. AF_INET)
    unsigned short   sin_port;     // číslo portu
    struct in_addr   sin_addr;     // IP adresa
    char             sin_zero[8];  // nulovacie pole
};
    • sin_family: Typ adresy, napr. AF_INET pre IPv4.
    • sin_port: Číslo portu, kde server čaká na pripojenie.
    • sin_addr: Štruktúra obsahujúca IP adresu servera/klienta.
    • sin_zero: Nulovacie pole, aby sa dosiahla správna veľkosť štruktúry.

    2. struct sembuf sem_b[1]:
Štruktúra sembuf sa používa na definovanie operácií nad semaforom v rámci volania semop().
struct sembuf {
    short sem_num;  // index semafora v sade
    short sem_op;   // hodnota, ktorá sa má pridať/odobrať
    short sem_flg;  // príznaky operácie
};
    • sem_num: Index semafora v sade.
    • sem_op: Hodnota, ktorá sa má pridať (ak kladná) alebo odobrať (ak záporná) k hodnote semafora.
    • sem_flg: Príznaky operácie, napr. 0 pre blokovanie, IPC_NOWAIT pre neblokujúce volanie.
9 Príručka používateľa  detailný sprievodca programom
Hlavným zámerom tohto programu je poskytnúť prax a pohľad do oblasti komunikácie a synchronizácie medzi procesmi. Tento projekt zahŕňa viacero procesov, ktoré spolupracujú na vytvorení komplexnej siete, využívajúc rôzne mechanizmy medziprocesovej komunikácie a synchronizácie.

Program sa spúšťa z príkazového riadku pomocou príkazu:
./zadanie <číslo_tcp_portu> <číslo_udp_portu> 
Je dôležité spomenúť, že pre správne fungovanie programu je nevyhnutná predchádzajúca kompilácia pomocou príkazu:
make all
ktorý zabezpečuje kompiláciu všetkých procesov vrátane hlavného programu.
Pred spustením programu je potrebné mať k dispozícii vstupné súbory p1.txt a p2.txt. Obsah týchto súborov sa postupne prenáša medzi jednotlivými procesmi, pričom každý proces pridáva vlastnú značku k prenášaným údajom. Nakoniec sú tieto údaje zapísané do súboru serv2.txt. Týmto spôsobom program demonštruje vzájomnú komunikáciu a koordináciu procesov v rámci komplexného systému.

10.1 proc_p1.cpp
#include <stdio.h>
#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdlib.h>
#include <signal.h>
#include <string.h>

void handler(int signum);

int P1;
int file;
char line[151], buff;

int main(int argc, char *argv[]) {

    // HANDLER SIGNALU
    (void) signal(SIGUSR1, handler);

    // POCET ARGUMENTOV
    if (argc != 2) {  // Opravený podmienkový výraz pre počet argumentov
        perror("Zlý počet argumentov");
        exit(EXIT_FAILURE);
    }

    // ZISKANIE IDENTIFIKACNEHO CISLA PIPE Z STDIN
    P1 = atoi(argv[1]);

    // OTVORENIE SUBORU NA CITANIE

#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <netinet/in.h>
#include <sys/socket.h>
#include <sys/ipc.h>
#include <fcntl.h>
#include <unistd.h>
#include <netdb.h>
#include <arpa/inet.h>
#include <sys/shm.h>
#include <sys/sem.h>
#include <signal.h>
#include <sys/types.h>
#include <errno.h>

int main(int argc, char *argv[]) {
    // odoslanie signalu hlavnemu procesu
    kill(getppid(), SIGUSR1);

    // Inicializácia štruktúry pre serverovú adresu
    struct sockaddr_in server_addr;

    // Overenie, či sú zadané správne parametre
    if (argc < 3) {
        exit(-1);
    }

    // Konverzia argumentov na čísla
    int shm2 = atoi(argv[1]);
    int S2 = atoi(argv[2]);
    int port = atoi(argv[3]);

    // Buffer pre prenos dát
    char buff[150];

    // Pripojenie sa na zdieľanú pamäť
    char *shmaddr = (char *)shmat(shm2, NULL, 0);

    // Vytvorenie socketu pre komunikáciu s serverom
    printf("Proces D vytvara socket.\n");
    int socket_id = socket(AF_INET, SOCK_STREAM, 0);

    // Nulovanie štruktúry pre serverovú adresu
    bzero((char *)&server_addr, sizeof(server_addr));

    // Nastavenie parametrov serverovej adresy
    server_addr.sin_family = AF_INET;
    server_addr.sin_addr.s_addr = inet_addr("127.0.0.1");
    server_addr.sin_port = htons(port);

    // Pripojenie sa na server
    if (connect(socket_id, (struct sockaddr *)&server_addr, sizeof(server_addr)) < 0) {
        perror("Proces D nepripojeny na server!");
    }

    // Inicializácia štruktúry pre semafory
    struct sembuf sem_b[1];

    // Nekonečný cyklus pre odosielanie dát
    while (1) {
        // Zvýšenie hodnoty semafora 
        sem_b[0].sem_op = 1;
        sem_b[0].sem_num = 0;
        sem_b[0].sem_flg = 0;

        // Operácia nad semaforom
        if (semop(S2, sem_b, 1) == -1) {
            exit(EXIT_FAILURE);
        }

        // Kopírovanie dát zo zdieľanej pamäte do buffra
        strcpy(buff, shmaddr);

        // Odoslanie dát na server
        write(socket_id, buff, (int)strlen(buff) + 1);

        // Vyčistenie buffra
        memset(buff, '\0', sizeof(buff));

        // Zníženie hodnoty semafora 
        sem_b[0].sem_op = -1;
        sem_b[0].sem_num = 1;
        sem_b[0].sem_flg = 0;

        // Operácia nad semaforom
        if (semop(S2, sem_b, 1) == -1) {
            exit(EXIT_FAILURE);
        }

        // Pauza na 1 sekundu
        sleep(1);
    }

    return 0;
}

#include <sys/types.h>

#include <sys/sem.h>
#include <sys/shm.h>
#include <signal.h>
#include <errno.h>
#include <sys/wait.h>

// Kľúče pre semafory a zdieľanú pamäť
#define SEM_KEY1 1000
#define SEM_KEY2 2000
#define SHM_KEY1 3000
#define SHM_KEY2 4000

// Deskriptory
int Serv1, Serv2, D, P1, P2, Pr, T, S;
int num_of_child_procs = 0;

// Funkcia na ukončenie všetkých potomkov po signále
void kill_all(int signum) {
    sleep(5);

    kill(P1, SIGKILL);
    kill(P2, SIGKILL);
    kill(Pr, SIGKILL);

    kill(T, SIGKILL);
    kill(S, SIGKILL);
    kill(D, SIGKILL);

    kill(Serv1, SIGKILL);
    kill(Serv2, SIGKILL);
}

// Funkcia na spracovanie signálu o prijatí ready signálu od potomka
void accepted_ready_signal(int signum) {
    printf("//--------------------//\n");
    num_of_child_procs++;
}

int main(int argc, char *argv[]) {
    // Kontrola počtu argumentov
    if (argc != 3) {
        perror("Zle spustene!");
    }

    // Handler pre signály
    (void)signal(SIGUSR2, kill_all);
    (void)signal(SIGUSR1, accepted_ready_signal);

    int port1 = atoi(argv[1]);
    int port2 = atoi(argv[2]);

    // Vytvorenie dvoch rúr (pipes)
    int pipe1[2], pipe2[2];
    if (pipe(pipe1) == -1 || pipe(pipe2) == -1) {
        perror("Vytvorenie rúr zlyhalo");
        exit(EXIT_FAILURE);
    }

    // Vytvorenie dvoch semaforov
    int sem_id1, sem_id2;
    sem_id1 = semget(SEM_KEY1, 2, IPC_CREAT | 0666);
    sem_id2 = semget(SEM_KEY2, 2, IPC_CREAT | 0666);

    if (sem_id1 == -1 || sem_id2 == -1) {
        perror("Vytvorenie semaforov zlyhalo");
        exit(EXIT_FAILURE);
    }

    // Inicializácia semaforov
    semctl(sem_id1, 0, SETVAL, 0);
    semctl(sem_id2, 0, SETVAL, 0);
    semctl(sem_id1, 1, SETVAL, 0);
    semctl(sem_id2, 1, SETVAL, 0);

    // Vytvorenie dvoch zdieľaných pamätí
    int shm_id1, shm_id2;
    size_t shm_size = 256;

    shm_id1 = shmget(SHM_KEY1, shm_size, IPC_CREAT | 0666);
    shm_id2 = shmget(SHM_KEY2, shm_size, IPC_CREAT | 0666);

    if (shm_id1 == -1 || shm_id2 == -1) {
        perror("Vytvorenie zdieľanej pamäti zlyhalo");
        exit(EXIT_FAILURE);
    }

    printf("Rúry, semafory a zdieľaná pamäť boli úspešne vytvorené.\n");

    // Konverzia čísel na reťazce
    char pipe1_str_W[20], pipe2_str_W[20], pipe1_str_R[20], pipe2_str_R[20];
    char sem1_str[20], sem2_str[20];
    char shm1_str[20], shm2_str[20];
    char port1_str[20], port2_str[20];

    sprintf(pipe1_str_W, "%d", pipe1[1]);
    sprintf(pipe2_str_W, "%d", pipe2[1]);
    sprintf(pipe1_str_R, "%d", pipe1[0]);
    sprintf(pipe2_str_R, "%d", pipe2[0]);

    sprintf(sem1_str, "%d", sem_id1);
    sprintf(sem2_str, "%d", sem_id2);

    sprintf(shm1_str, "%d", shm_id1);
    sprintf(shm2_str, "%d", shm_id2);

    sprintf(port1_str, "%d", port1);
    sprintf(port2_str, "%d", port2);

    // Spustenie potomkov a kontrola úspechu
    Serv1 = fork();
    if (Serv1 == 0) {
        if ((execlp("./proc_serv1", "proc_serv1", port1_str, port2_str, NULL)) < 0) {
            printf("chyba");
            exit(EXIT_FAILURE);
        }
        exit(EXIT_SUCCESS);
    } else if (Serv1 < 0) {
        printf("chyba\n");
        exit(EXIT_FAILURE);
    }

    while (num_of_child_procs < 1) {
        pause();
    }

    Serv2 = fork();
    if (Serv2 == 0) {
        if ((execlp("./proc_serv2", "proc_serv2", port2_str, NULL)) < 0) {
            printf("chyba");
            exit(EXIT_FAILURE);
        }
        exit(EXIT_SUCCESS);
    } else if (Serv2 < 0) {
        printf("chyba\n");
        exit(EXIT_FAILURE);

        pause();

    D = fork();
    if (D == 0) {
        if ((execlp("./proc_d", "proc_d", shm2_str, sem2_str, port1_str, NULL)) < 0) {
            printf("chyba");
            exit(EXIT_FAILURE);
        }
        exit(EXIT_SUCCESS);
    } else if (D < 0) {
