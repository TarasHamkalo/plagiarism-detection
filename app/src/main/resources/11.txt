        1.2. Popis procesov
PROCES Zadanie (vypracovaný študentom, nie je zakreslený v diagrame)
Spúšťanie
zadanie <číslo portu 1> <číslo portu 2>
Funkcia
Parametre hlavného programu sú čísla portov pre servery Serv1 (TCP) a Serv2 (UDP). Tieto čísla je potrebné týmto procesom odovzdať. Program Zadanie nech vyhradí všetky zdroje (pre medziprocesovú komunikáciu) a nech spustí všetky procesy. Všetky procesy nech sú realizované ako samostatné programy.
PROCES Pr
Spúšťanie
proc_pr
Funkcia
Proces Pr pošle signál SIGUSR1 svojmu hlavnému procesu (Zadanie) na signalizáciu, že je pripravený. Proces Pr si údaje bude žiadať:
    • Ak pošle signál (SIGUSR1) procesu P1, nech tento proces (P1) zapíše slovo prečítané zo súboru p1.txt.
    • To isté platí aj pre proces P2 a p2.txt. Teda, ak proces Pr pošle signál (SIGUSR1) procesu P2 nech do rúry R1 zapíše slovo proces P2 zo súboru p2.txt.
Proces Pr k slovu prijatému z rúry R1 pridá svoju značku a zapíše nové slovo do rúry R2.

PROCES S
Spúšťanie
proc_s
Funkcia
Proces S pošle signál SIGUSR1 svojmu hlavnému procesu (Zadanie) na signalizáciu, že je (proces S) pripravený. Proces S príjme slovo zo zdieľanej pamäte SM1 so synchronizáciou semaforom S1 (pozri časť o semaforoch v časti „Popis komunikácie“), pripíše k nemu svoju značku a zapíše ho do zdieľanej pamäte SM2 so synchronizáciou semaforom S2.
PROCES Serv1
Spúšťanie
proc_serv1 <číslo portu 1> <číslo portu 2>
Funkcia
Proces Serv1 vytvorí TCP server (na porte <číslo portu 1>), ktorý bude prijímať TCP pakety. Server prijaté slová označí svojou značkou a pošle ich ďalej na UDP server (port <číslo portu 2>). Čísla portov 1 a 2 sú argumenty hlavného procesu (pozri kapitolu „PROCES Zadanie“). Proces Serv1 pošle signál SIGUSR1 svojmu hlavnému procesu (Zadanie) na signalizáciu, že je (proces Serv1) pripravený. TCP aj UDP server nech vytvorený na lokálnom počítači, teda na počítači „127.0.0.1“ (pozor, nie „localhost“!).

        1.3. Popis komunikácie
Semafor S1
Pre semafor S1 je potrebné vytvoriť dvojicu semaforov. Proces T nech sa riadi podľa semaforu S1[0] a proces S sa bude riadiť podľa semaforu S1[1], pričom nastavený semafor S1[0] (rozumej nastavený na hodnotu 1) nech znamená, že proces T môže zapisovať do zdieľanej pamäte (SM1). Nastavený semafor S1[1] nech znamená, že proces S môže zo zdieľanej pamäte (SM1) údaje čítať.
Semafor S2
Pre semafor S2 je potrebné vytvoriť dvojicu semaforov. Proces S nech sa riadi podľa semaforu S2[0] a proces D sa bude riadiť podľa semaforu S2[1]. Pričom nastavený semafor S2[0] (rozumej nastavený na hodnotu 1) nech znamená, že proces S môže zapisovať do zdieľanej pamäte (SM2). Nastavený semafor S2[1] nech znamená, že proces D môže zo zdieľanej pamäte (SM2) údaje čítať.

    4. Analýza problematiky
Program zadanie slúži k integrácii všetkých častí zadania a implementuje mechanizmy medziprocesovej komunikácie. Inicializuje signály SIGUSR1 a SIGUSR2, rúry R1 a R2, zdieľané pamäte sMem1 a sMem2, a semafory sem1 a sem2. Tieto prostriedky uľahčujú komunikáciu medzi jednotlivými procesmi.
Podprocesy proc_p1, proc_p2, proc_t, proc_d, a proc_serv2 sú spustené pomocou funkcie fork a komunikujú medzi sebou prostredníctvom rúr (proc_p1, proc_p2, a proc_pr), zdieľanej pamäte a semaforov (proc_t, proc_s, a proc_d). Proces proc_d komunikuje s procesom proc_serv1 prostredníctvom TCP paketov, zatiaľ čo proces proc_serv1 komunikuje pomocou UDP s procesom proc_serv2.
Program zabezpečuje odhalenie chýb a umožňuje ukončiť všetky procesy po prijatí signálu SIGUSR2, ktorý dostane z podprocesu proc_serv2. Týmto spôsobom je dosiahnutá kontrola chodu programu a bezpečné ukončenie v prípade potreby.

        5.2. Dátové štruktúry
            5.2.1. Rúra
pipe() vytvára jednosmerný dátový kanál, do ktorého možno zapisovať alebo čítať. V podstate otvára deskriptor (podobne ako stdin a stdout), ktorý môžu používať ostatní. Údaje zapísané na jednom konci možno čítať z druhého konca

            5.2.2. Semafor
Semafory sa používajú na prevenciu”predbiehania” stavov. Sú to premenné, ktoré zabraňujú alebo umožňujú pokračovaniu a zastaveniu procesov. V tomto prípade sa používajú na to, aby umožnili programu zapisovať údaje a zastaviť druhý program kým sa dokončí, a potom tento proces obrátiť aby druhý program mohol čítať uvedené údaje.

            5.2.3. Server
Server možno rozdeliť na dve časti, klienta a server.
Server je pasívny a jeho úlohou je prijímať a spracúvať údaje, ktoré sa mu posielajú, počúvaním.
Klient je však aktívny a posiela údaje na server. 
Tieto dva procesy môžu byť na rôznych počítačoch a môžu to byť dokonca rôzne typy.

            5.2.4. Zdieľaná pamäť
Zdieľaná pamäť je priestor pamäte, ktorý môžu zdieľať dva alebo viac procesov. Každý proces z nej môže čítať alebo zapisovať. Alternatívou k zdieľanej pamäti by boli named pipes alebo fifo, ale rozdiel je v tom že tieto procesy musia najprv prejsť jadrom, čo môže byť v niektorých situáciách problém.

        5.3. Spôsob synchronizácie
Synchronizácia bola potrebná, aby sa zabránilo predbiehania procesov.
Predbiehania znamená, že jeden proces sa môže spustiť skôr ako druhý a pokaziť výsledok.
V tomto projekte sme používali najmä signály a semafory.
Signály sa používali tak že každý program vyslal signál SIGUSR1, ktorý signalizoval že je pripravený a hlavný program sa zastavil kým nedostal signál.

Zadanie IPC slúži na riadenie medziprocesovej komunikácie medzi rôznymi procesmi. Cielom je použitie rôznych mechanizmov IPC: rúry, zdielaná pamäť, semafory v prostredí UNIX.

Pozostáva z viacerých modulárných procesov, ktoré sú pripojené procesom “zadanie.cpp”, ktorý je hlavný modul.

Obsahuje dátové štruktúry:

Program musí byť najprv skompilovaný zadaním príkazu "make".

            perror("Failed executing proc_serv2");
            exit(EXIT_FAILURE);
        }
        exit(EXIT_SUCCESS);
    }
    pause();

    switch(D = fork())
    {

        perror("Fork failed on D");
        exit(EXIT_FAILURE);

        if(execl("proc_d", "proc_d",argv[1],s_sMem2,s_sem2, NULL) == -1) {
            perror("Failed executing proc_d");
            exit(EXIT_FAILURE);
        }
        exit(EXIT_SUCCESS);

void readFile(int signum);

int intP1,fd;

int main(int argc, char *argv[]) {
    (void)signal(SIGUSR1,readFile);
    fd = open("p1.txt", O_RDONLY);
    if(fd == -1) perror("Error in proc_p1"), exit(1);

    intP1 = atoi(argv[1]);
   
    kill(getppid(),SIGUSR1);

    while(1) {
        sleep(5);
    }
    close(fd);
    return 0;
}

void readFile(int signum) {
    char buffer[1];
    do{
        read(fd,&buffer,1);
        write(intP1,buffer,1);
    }while(buffer[0] !='\n');
}

#include <sys/types.h>
#include <sys/stat.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/ipc.h>
#include <sys/sem.h>
#include <sys/shm.h>
#include <signal.h>
#include <errno.h>

int main(int argc, char const *argv[]){
    struct sembuf semaphore;
    char line[500];
    char buff;

    int pipe = atoi(argv[1]);
    char *ptr = (char*) (shmat(atoi(argv[2]),NULL,00));      int sem = atoi(argv[3]);

    kill(getppid(), SIGUSR1);

    while(1){
        int i = 0;

        do{
            read(pipe,&buff,1);
            line[i] = buff;
            i++;
        }while(buff != '\n');
        line[i-1] = '\0';
       
        semaphore.sem_num = 1;
        semaphore.sem_op = 1;
        semaphore.sem_flg = SEM_UNDO;
        if(semop(sem,&semaphore,1) == -1)exit(EXIT_FAILURE);


        strcpy(ptr,line);


        semaphore.sem_num = 0;
        semaphore.sem_op = -1;
        semaphore.sem_flg = SEM_UNDO;
        if(semop(sem, &semaphore, 1) == -1) exit(EXIT_FAILURE);
    }
  return 0;
}

proc_serv2.cpp
#include <string.h>
#include <sys/types.h>
#include <sys/socket.h>
#include <netdb.h>
#include <stdlib.h>
#include <stdio.h>
#include <signal.h>
#include <errno.h>
#include <unistd.h>
#include <fcntl.h>

int main(int agrc, char *argv[]) {
    struct addrinfo hints, *res;
    int sockfd;

    memset(&hints,0,sizeof(hints));
    hints.ai_family = AF_INET;
    hints.ai_socktype = SOCK_DGRAM;

    getaddrinfo("127.0.0.1",argv[1],&hints,&res);

    sockfd = socket(res->ai_family,res->ai_socktype,res->ai_protocol);
/*UDP connections rely on messages, they do not need to connect*/

    if(bind(sockfd, res->ai_addr, res->ai_addrlen) == -1) perror("(serv2) Failed on bind"),exit(1);

    kill(getppid(),SIGUSR1);

    ///////////////////////////////////////////////////////////////////////////

    char buf[256];
    int fd;
    if((fd = open("serv2.txt",O_CREAT|O_WRONLY|O_TRUNC,0666)) < 0){
        perror("(serv2) Error opening file");
        exit(EXIT_FAILURE);
    }


    for(int i = 0;i < 10;i++) {
        memset(buf,'\0',sizeof(buf));
        if(recv(sockfd,buf,256,0) == -1) perror("(serv2) Error receiving data!");
        if(write(fd,buf,strlen(buf))<0) perror ("(serv2) Error writing data!");
        if(write(fd,"\n",1)<0) perror ("(serv2) Error writing data!");

        printf("Received data:%s\n",buf);
        sleep(1);
    }

    close(sockfd);
    close(fd);
    kill(getppid(),SIGUSR2);
}
